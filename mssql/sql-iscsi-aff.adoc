[.lead]
Deploy SQL Server 2025 on Windows Server 2025 with user databases, transaction logs, TempDB, and log backups on iSCSI LUNs on a NetApp AFF system. This procedure includes configuring iSCSI on the ONTAP SVM, the initiator group and LUNs, the Windows iSCSI initiator, MPIO and disks, and installing SQL Server.

[[intro-scope]]
== Scope

This procedure deploys a standalone SQL Server 2025 instance on a single Windows Server 2025 host, with user databases, transaction logs, TempDB, and log backups on iSCSI LUNs.
The same storage design applies to SQL Server failover cluster instances (FCI) and Always On availability groups, but their cluster-specific configuration is not covered.
SQL Server performance tuning and sizing are also out of scope.
For the benefits, solution components, design principles, an explanation of how multipathing works, and data protection with NetApp Console Backup and Recovery, see link:sql-iscsi-aff-overview.html[Learn about SQL Server 2025 on NetApp AFF with iSCSI LUNs].

[[intro-audience]]
== Audience

This procedure is intended for:

* *Storage administrators*, who configure the ONTAP cluster, the SVM, the iSCSI LIFs, the initiator group and the LUNs.
* *Windows administrators*, who prepare the Windows Server 2025 host, the iSCSI initiator, MPIO and the disks.
* *Database administrators*, who install and configure SQL Server 2025 and set up backup and recovery.

Basic knowledge of ONTAP System Manager, Windows Server and SQL Server administration is assumed.

[[prerequisites]]
== Prerequisites

Make sure that the following requirements are met before you start:

.NetApp ONTAP
* The AFF HA pair is installed, and the cluster is set up and healthy.
* The iSCSI license is installed. It is included in ONTAP One.
* At least one data aggregate (local tier) exists on each node.
* The SVM exists. In this procedure, the existing SVM `{svm}` is used; iSCSI is added to it. To create a dedicated SVM for SAN, use menu:Cluster[Storage VMs > Add] and select *iSCSI* as access protocol.
* The data network ports, broadcast domain and (optionally) VLANs for the iSCSI LIFs are configured. In the lab, the broadcast domain `MT9000` uses jumbo frames.
* Time is synchronized between the cluster, the host and Active Directory through NTP.

.Network
* The SQL Server host has at least one, preferably two, dedicated NICs for iSCSI in the iSCSI subnet or VLAN.
* The MTU is the same end to end (host NIC, switches, ONTAP ports). Verify jumbo frames with `ping -f -l 8972 <LIF-IP>` from the host.

.Windows Server
* Windows Server 2025 (Desktop Experience) is installed, patched and joined to the domain.
* The NetApp Windows Host Utilities in a version supported for Windows Server 2025 is available (see the https://imt.netapp.com/matrix/[NetApp Interoperability Matrix Tool (IMT)^]).
* The SQL Server 2025 installation media (ISO) and a valid product key (or a free edition) are available.

NOTE: Unlike SMB file shares, LUNs don't require a domain account for the SQL Server service.
The default virtual accounts (`NT Service\MSSQLSERVER`) can be used.
A domain account or gMSA is still recommended if the instance needs network access, for example to back up to a file share or for Kerberos authentication.

[[volume-settings]]
== Step 5: Review the volume and LUN settings

Review the space and snapshot settings of the four volumes.
System Manager uses sensible defaults; the following settings are recommended for SQL Server LUNs:

[cols="1,1,3",options="header"]
|===
|Setting |Value |Reason

|Space guarantee (volume)
|`none` (thin)
|Capacity is consumed only when data is written.

|LUN space reservation
|`disabled` (thin)
|Thin LUN in a thin volume.

|LUN space allocation
|`enabled`
|Enables SCSI UNMAP, so that space freed in NTFS is returned to ONTAP, and lets the host react correctly when the volume runs out of space.

|Snapshot policy
|`none`
|Snapshots that are not application-consistent are of no use for SQL Server. Backups are created by NetApp Console Backup and Recovery.

|Snapshot reserve
|`0` %
|Snapshot space is monitored with the volume autosize instead.

|Autosize
|`grow`, maximum about 130 % of the volume size
|Prevents the LUN from going offline when snapshots consume space.

|Storage efficiency
|enabled (default on AFF)
|Inline deduplication, compression and compaction have no measurable impact on SQL Server performance.
|===

Use the following commands to apply and verify the settings (shown for `sql_iscsi_1_data`):

[source,console]
----
cluster::> volume modify -vserver a50-sql -volume sql_iscsi_1_data -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 730GB
cluster::> lun modify -vserver a50-sql -path /vol/sql_iscsi_1_data/sql_iscsi_1_data_1 -space-allocation enabled
cluster::> volume show -vserver a50-sql -volume sql_iscsi_1_* -fields aggregate,size,space-guarantee,snapshot-policy,autosize-mode
----

NOTE: Changing `space-allocation` on an existing LUN requires the LUN to be offline.
Set it at creation time, or before the host connects to the LUN.

.PowerShell
--
The following commands bring the NetApp disks online, initialize them with GPT, create and format one NTFS volume with a 64K allocation unit size on each, and create the folders for SQL Server.

[source,powershell]
----
PS C:\> $layout = @{ 520GB = 'E','data'; 250GB = 'F','log'; 150GB = 'G','tempdb'; 300GB = 'H','Log backup' }
PS C:\> foreach ($d in Get-Disk | Where-Object FriendlyName -like 'NETAPP*') {
          $l = $layout[[int64]$d.Size]
          Set-Disk -Number $d.Number -IsOffline $false
          Set-Disk -Number $d.Number -IsReadOnly $false
          Initialize-Disk -Number $d.Number -PartitionStyle GPT
          New-Partition -DiskNumber $d.Number -UseMaximumSize -DriveLetter $l[0] |
            Format-Volume -FileSystem NTFS -AllocationUnitSize 65536 -NewFileSystemLabel $l[1] -Confirm:$false
        }
PS C:\> 'E:\data','F:\log','G:\tempdb\data','G:\tempdb\log','H:\backup' | ForEach-Object { New-Item -ItemType Directory -Path $_ }
PS C:\> Get-Volume -DriveLetter E,F,G,H | Format-Table DriveLetter,FileSystemLabel,FileSystem,AllocationUnitSize,Size
----
--

[[post-install]]
== Step 9: Verify the installation

Create a test database, and verify that its data and log files are on the NetApp LUNs and that the storage paths are healthy.

.Steps
. Open the SQL Server port in the Windows firewall:
+
[source,powershell]
----
PS C:\> New-NetFirewallRule -DisplayName "SQL Server (TCP 1433)" -Direction Inbound -Protocol TCP -LocalPort 1433 -Action Allow
----

. Install SQL Server Management Studio (SSMS) from the *Install SQL Server Management Tools* link in the Installation Center, or from the Microsoft website.

. Start SSMS and connect to the instance (`{host}`) with Windows authentication.
Create a test database; its data and log files default to `E:\data` and `F:\log`.

. Verify the file locations with T-SQL:
+
[source,sql]
----
SELECT DB_NAME(database_id) AS database_name,
       type_desc,
       name AS logical_name,
       physical_name,
       size * 8 / 1024 AS size_mb
FROM   sys.master_files
ORDER  BY database_id, type_desc;
----

. Verify that instant file initialization is enabled:
+
[source,sql]
----
SELECT servicename, service_account, instant_file_initialization_enabled
FROM   sys.dm_server_services;
----

. Verify the storage from the host and from ONTAP:
+
[source,powershell]
----
PS C:\> Get-Disk | Where-Object FriendlyName -like 'NETAPP*' | Format-Table Number,FriendlyName,Size,OperationalStatus,PartitionStyle
PS C:\> mpclaim -s -d
----
+
[source,console]
----
cluster::> lun show -vserver a50-sql -fields path,size,mapped,state
cluster::> vserver iscsi session show -vserver a50-sql
cluster::> qos statistics volume latency show -vserver a50-sql
----

. Optional: test the high availability.
Run a workload against the test database and perform an ONTAP takeover and giveback of the node that owns the data volume (`storage failover takeover -ofnode <node>` / `storage failover giveback -ofnode <node>`).
The workload pauses for a few seconds and continues; the databases stay online.

.What's next
Protect the databases with application-consistent snapshot backups.
For the architecture, the backup workflow and the benefits, see link:sql-iscsi-aff-overview.html#console[Data protection with NetApp Console Backup and Recovery].

== Use an ONTAP CLI script to configure the storage in one pass

The following script contains the complete storage configuration from this procedure.
Replace the values in angle brackets before you run it.

[source,console]
----
# --- iSCSI service and LIFs ----------------------------------------------
vserver add-protocols -vserver a50-sql -protocols iscsi
vserver iscsi create -vserver a50-sql -target-alias a50-sql

network interface create -vserver a50-sql -lif a50-sql_iscsi_n1_1 -service-policy default-data-iscsi -home-node SAPCC-A50-01 -home-port <port> -address 192.168.175.134 -netmask 255.255.255.0
network interface create -vserver a50-sql -lif a50-sql_iscsi_n1_2 -service-policy default-data-iscsi -home-node SAPCC-A50-01 -home-port <port> -address 192.168.175.135 -netmask 255.255.255.0
network interface create -vserver a50-sql -lif a50-sql_iscsi_n2_1 -service-policy default-data-iscsi -home-node SAPCC-A50-02 -home-port <port> -address 192.168.175.136 -netmask 255.255.255.0
network interface create -vserver a50-sql -lif a50-sql_iscsi_n2_2 -service-policy default-data-iscsi -home-node SAPCC-A50-02 -home-port <port> -address 192.168.175.137 -netmask 255.255.255.0

# --- Initiator group -----------------------------------------------------
lun igroup create -vserver a50-sql -igroup sql-iscsi-1 -protocol iscsi -ostype windows -initiator iqn.1991-05.com.microsoft:sql-iscsi-1.sapcc.stl.netapp.com

# --- Volumes -------------------------------------------------------------
volume create -vserver a50-sql -volume sql_iscsi_1_data      -aggregate <aggr_node1> -size 560GB -space-guarantee none -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 730GB
volume create -vserver a50-sql -volume sql_iscsi_1_log       -aggregate <aggr_node2> -size 270GB -space-guarantee none -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 350GB
volume create -vserver a50-sql -volume sql_iscsi_1_tempdb    -aggregate <aggr_node2> -size 165GB -space-guarantee none -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 210GB
volume create -vserver a50-sql -volume sql_iscsi_1_logbackup -aggregate <aggr_node1> -size 325GB -space-guarantee none -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 420GB

# --- LUNs ----------------------------------------------------------------
lun create -vserver a50-sql -path /vol/sql_iscsi_1_data/sql_iscsi_1_data_1           -size 520GB -ostype windows_2008 -space-reserve disabled -space-allocation enabled
lun create -vserver a50-sql -path /vol/sql_iscsi_1_log/sql_iscsi_1_log_1             -size 250GB -ostype windows_2008 -space-reserve disabled -space-allocation enabled
lun create -vserver a50-sql -path /vol/sql_iscsi_1_tempdb/sql_iscsi_1_tempdb_1       -size 150GB -ostype windows_2008 -space-reserve disabled -space-allocation enabled
lun create -vserver a50-sql -path /vol/sql_iscsi_1_logbackup/sql_iscsi_1_logbackup_1 -size 300GB -ostype windows_2008 -space-reserve disabled -space-allocation enabled

# --- LUN mapping ---------------------------------------------------------
lun mapping create -vserver a50-sql -path /vol/sql_iscsi_1_data/sql_iscsi_1_data_1           -igroup sql-iscsi-1
lun mapping create -vserver a50-sql -path /vol/sql_iscsi_1_log/sql_iscsi_1_log_1             -igroup sql-iscsi-1
lun mapping create -vserver a50-sql -path /vol/sql_iscsi_1_tempdb/sql_iscsi_1_tempdb_1       -igroup sql-iscsi-1
lun mapping create -vserver a50-sql -path /vol/sql_iscsi_1_logbackup/sql_iscsi_1_logbackup_1 -igroup sql-iscsi-1

# --- Verification ----------------------------------------------------------
vserver iscsi show -vserver a50-sql
network interface show -vserver a50-sql -data-protocol iscsi
lun show -vserver a50-sql -fields path,size,ostype,space-allocation,mapped,state
lun mapping show -vserver a50-sql
vserver iscsi session show -vserver a50-sql
----

TIP: Distribute the volumes across the aggregates of both nodes, for example data and log backup on node 1, and log and TempDB on node 2.

[[ps-script]]
== Use a PowerShell script to configure the host in one pass

The following script contains the complete host configuration from this procedure.
Run it in an elevated PowerShell session; the MPIO part requires a restart.

[source,powershell]
----
# --- Part 1: iSCSI service and MPIO (restart required) ------------------------
Set-Service -Name MSiSCSI -StartupType Automatic
Start-Service -Name MSiSCSI
(Get-InitiatorPort | Where-Object ConnectionType -eq 'iSCSI').NodeAddress   # initiator IQN for the igroup
Install-WindowsFeature -Name Multipath-IO
Enable-MSDSMAutomaticClaim -BusType iSCSI
# Install NetApp Windows Host Utilities (MPIO support) now, then:
Restart-Computer

# --- Part 2: connect the iSCSI sessions (after the LUNs are mapped in ONTAP) ---
$initiatorIP = '192.168.175.44'
$lifs        = '192.168.175.134','192.168.175.135','192.168.175.136','192.168.175.137'
New-IscsiTargetPortal -TargetPortalAddress $lifs[0] -InitiatorPortalAddress $initiatorIP
$target = Get-IscsiTarget | Where-Object NodeAddress -like 'iqn.1992-08.com.netapp:*'
foreach ($lif in $lifs) {
    Connect-IscsiTarget -NodeAddress $target.NodeAddress -TargetPortalAddress $lif `
        -InitiatorPortalAddress $initiatorIP -IsMultipathEnabled $true -IsPersistent $true
}
Get-IscsiSession | Format-Table TargetNodeAddress,InitiatorPortalAddress,IsConnected,IsPersistent
mpclaim -s -d

# --- Part 3: disks, volumes and folders ---------------------------------------
$layout = @{ 520GB = 'E','data'; 250GB = 'F','log'; 150GB = 'G','tempdb'; 300GB = 'H','Log backup' }
foreach ($d in Get-Disk | Where-Object FriendlyName -like 'NETAPP*') {
    $l = $layout[[int64]$d.Size]
    Set-Disk -Number $d.Number -IsOffline $false
    Set-Disk -Number $d.Number -IsReadOnly $false
    Initialize-Disk -Number $d.Number -PartitionStyle GPT
    New-Partition -DiskNumber $d.Number -UseMaximumSize -DriveLetter $l[0] |
        Format-Volume -FileSystem NTFS -AllocationUnitSize 65536 -NewFileSystemLabel $l[1] -Confirm:$false
}
'E:\data','F:\log','G:\tempdb\data','G:\tempdb\log','H:\backup' | ForEach-Object { New-Item -ItemType Directory -Path $_ -Force }

# --- Part 4: firewall for SQL Server -----------------------------------------
New-NetFirewallRule -DisplayName "SQL Server (TCP 1433)" -Direction Inbound -Protocol TCP -LocalPort 1433 -Action Allow
----
